# Service Level Objectives (SLO) — app

## 1. Service Description
Простой HTTP API на Python/Flask. Отдаёт `{"status":"ok"}` на `/` и метрики Prometheus на `/metrics`.

## 2. SLI (Service Level Indicators) — что измеряем
- **Availability**: Доля успешных запросов (HTTP 2xx/3xx) от общего числа.
- **Latency**: 95-й перцентиль времени ответа на главный эндпоинт.

## 3. SLO (Service Level Objectives) — к чему стремимся (окно 30 дней)
- **Availability SLO**: 99.5% успешных запросов.
- **Latency SLO**: 95% запросов должны отвечать быстрее 300 мс.

## 4. Error Budget — сколько можно ошибаться
- **Availability**: 0.5% от всех запросов за 30 дней (около 3.6 часов полного простоя в месяц).
- **Latency**: 5% запросов могут превышать 300 мс.

## 5. Error Budget Policy — что делаем, когда бюджет кончился
Если Error Budget исчерпан (мы нарушили SLO):
1. Вводится **Feature Freeze** (заморозка выкатки новых фич).
2. Команда переключается на задачи по повышению надёжности.
3. Проводится **blameless postmortem** (разбор без поиска виноватых).
4. Возобновление выкаток только после восстановления бюджета.

## 6. Alerting Strategy
- Алерт срабатывает, когда **burn rate** (скорость сжигания бюджета) превышает 10x.
- Каждый алерт должен быть actionable (можно что-то сделать) и user-visible (влияет на пользователей).
